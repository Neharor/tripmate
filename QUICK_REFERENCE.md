## 🎯 API vs LLM vs ML MODEL

### What's the difference?

| Aspect | API | LLM | ML Model |
|--------|-----|-----|----------|
| **Definition** | External service call | Large Language Model (AI) | Traditional machine learning |
| **Example** | Amadeus Flight API | Groq AI (llama-3.1) | scikit-learn, TensorFlow |
| **Data Source** | Real-time external | Generated/predicted | Trained predictions |
| **Speed** | Fast (2-7 sec) | Medium (5-10 sec) | Fast (< 1 sec) |
| **Accuracy** | 100% factual | 85-90% realistic | Depends on training |
| **Cost** | Per API call | Per token | One-time training |
| **Use Case** | Flight prices, hotels | Reasoning, curation | Pattern recognition |
| **TripMate Usage** | ✅ Flights, Hotels | ✅ Itinerary, Activities | ❌ Not using |

## 🔍 DETAILED COMPONENT BREAKDOWN

### 1. FlightAgent

**Code:** `backend/agents/flight.py`

**Data Flow:**
```
User input → FlightAgent
              ↓
    Try: Amadeus API (search_flights)
         ├─ Success: Real flight data ✅
         └─ Failure: LLM fallback
              ↓
    Format with templates (NO LLM)
              ↓
    Return: 3 flight options
```

**Data Source:**
- **Primary:** Amadeus Flight Offers API (`GET /v2/shopping/flight-offers`)
- **Fallback:** Groq AI LLM (llama-3.1-8b-instant)
- **Processing:** Python templates (NO ML model)

**Example API Response:**
```json
{
  "price": { "total": "450.00", "currency": "USD" },
  "itineraries": [{
    "segments": [{
      "departure": { "iataCode": "NRT", "at": "2025-11-20T14:30" },
      "arrival": { "iataCode": "GOI", "at": "2025-11-20T22:45" },
      "carrierCode": "AI"
    }]
  }]
}
```

---

### 3. ItineraryAgent

**Code:** `backend/agents/itinerary.py`

**Data Flow:**
```
User input → ItineraryAgent
              ↓
    LLM generates schedule
    (Complex reasoning: time optimization,
     interest matching, budget allocation)
              ↓
    Return: Day-by-day itinerary
```

**Data Source:**
- **100% LLM:** Groq AI (llama-3.1-8b-instant)
- **No API calls**
- **No ML models**

**Why LLM?**
- Complex reasoning needed
- Time optimization (group nearby attractions)
- Interest-based prioritization
- Realistic scheduling (travel time, queues)

---

### 4. ActivitiesAgent

**Data Flow:**

```
User input → ActivitiesAgent
              ↓
    LLM curates activities
    (Interest-based: 60% adventure + 40% food)
              ↓
    Return: Bookable activities
```

**Data Source:**
- **100% LLM:** Groq AI (llama-3.1-8b-instant)
- **No API calls**
- **No ML models**

- Personalization (interest matching)

- Dietary preferences
- Activity curation

### 5. WeatherAgent

**Code:** `backend/agents/weather.py`

**Data Flow:**
```
User input → WeatherAgent
              ↓
    If API key exists: OpenWeatherMap API
    Else: LLM generates weather (current)
              ↓
    Return: Weather recommendations
```

**Data Source:**
- **Current:** LLM (Groq AI) - 100%

### 6. Entity Extractor

**Code:** `backend/agents/entity_extractor.py`

**Data Flow:**
```
Conversation → EntityExtractor
              ↓
    LLM extracts:
    - destination, departure_city
    - dates, budget, interests
    - food preferences
              ↓
    Python validation (prevent overwriting)
              ↓
    Return: Structured entities
```

**Data Source:**
- **LLM:** Groq AI - 100%
- **Validation:** Python rules (main.py lines 125-140)
